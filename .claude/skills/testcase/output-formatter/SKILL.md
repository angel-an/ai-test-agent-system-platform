# 测试用例输出格式规范 Skill

## 激活场景
- 生成最终测试用例前，确定输出格式
- 用户要求导出特定格式（Excel/CSV/JSON/Markdown）
- 需要将测试用例导入测试管理工具
- 需要格式化已有的测试用例

---

## 用例编号命名规范

```
格式：[模块汉语拼音首字母大写]+[四位流水号]

示例：
HTWH0001   → 合同维护模块，第1条
HTWH0002   → 合同维护模块，第2条
```

---

## 字段属性规范（公司标准）

每个测试用例必须包含以下必填核心属性，严格遵循对应的值域：

| 字段名 | 规范要求 |
|--------|---------|
| **用例编号** | 如：HTWH0001 |
| **功能模块 / module / 所属模块** | **必填**。最低层次模块的上一级模块名称，必须从需求文档的功能矩阵中提取，不可留空。 |
| **用例名称** | **必须**带 `应用端-模块` 前缀，格式：`应用端-模块[动词][操作对象][条件/场景]`。目的：通过标题即可识别用例归属的客户端及验证目标。应用端取值如：Web端、APP端（iOS）、APP端（Android）、小程序端、H5端、管理后台、API接口 等 |
| **测试检查要点** | 简明概括本用例的测试关注点/重点 |
| **测试类型** | 必选其一：正常类测试 / 异常类测试 / 兼容性测试 / UI/用户体验测试 / 业务流程测试 / 安全性测试 / 性能测试 |
| **关键词** | 必选其一：正向 / 反向 / 边界。正向=验证预期行为；反向=验证异常/拒绝行为；边界=验证临界/极限值。**必须独立成字段，不要塞进备注** |
| **优先级** | 必选其一：高 / 中 / 低 |
| **前置条件** | 测试执行的前提条件，无则可空 |
| **输入数据** | 影响测试结果的关键数据，非核心参数写“默认” |
| **测试步骤** | 操作位置与动作，强调部分用“【】”或“""”标识，层级用“->”分隔 |
| **预期结果** | 明确、具体、可验证的结果，不可使用模糊词汇 |
| **备注** | 关联需求编号、风险说明等 |

## 输出格式一：标准Markdown格式（默认）

每个测试用例使用以下Markdown模板输出：

```markdown
---

### [用例编号]：应用端-模块[用例名称]

> **功能模块**：[模块名] ｜ **优先级**：[高/中/低] ｜ **测试类型**：[测试类型]
> **测试检查要点**：[简要说明测试重点]

**前置条件**：
- [条件1，具体且可验证]
- [条件2]

**输入数据**：
- [关键数据1]
- [关键数据2]

**测试步骤**：
1. [具体操作，使用主动动词：输入/单击/选择] -> [操作的UI元素或接口]
2. [具体操作] -> [操作对象]

**预期结果**：
1. ✅ [UI层/接口层/数据层：具体可验证的表现，如提示文案、状态变化]
2. ✅ [如有多个验证点，逐条列出]

**备注**：关联需求 `REQ-[ID]` | 风险级别：[高/中/低]
```

- 低优先级：N

## 输出格式四：Excel格式（推荐导出）

当用户要求导出 Excel 文件时，调用 `export_testcases_to_excel` 工具。文件自动保存到服务器 `workspace/uploads/` 目录，用户可通过前端导出按钮下载。调用时需传入 `test_cases`（用例列表）和可选的 `requirement_name`（需求名称，用于文件命名）。

**Excel 导出字段强制要求**：
- `module` / `所属模块` 字段**必须**包含有效值，值来源于需求文档功能矩阵中的模块名称。禁止为空字符串或 null。
