# 营销云 - 消息管理 (Message Management) 测试计划

## 1. 概述

### 1.1 功能描述
消息管理 (Message Management) 是营销云后台系统模块下的核心功能，用于管理消息模板和渠道配置。主要包括两大功能模块：

- **消息模板 (Message Templates)**: 管理所有消息模板，支持模板的创建、搜索、查看、启用/禁用等操作。消息模板包含名称、状态、渠道类型、消息类型、审核状态等信息。
- **渠道配置 (Channel Configuration)**: 管理消息发送渠道，支持查看渠道信息、禁用渠道、同步模板等操作。

本功能位于营销云侧边栏菜单 → 系统 → 消息管理，供管理员进行消息模板的统一管理和渠道配置维护。

### 1.2 测试目标
- 验证从控制台登录到营销云消息管理页面的完整导航流程
- 验证消息模板列表的正常加载与元素完整性
- 验证按模版名称、模版ID搜索消息模板功能
- 验证查看消息模板详情功能
- 验证消息模板的启用/禁用功能
- 验证渠道配置页面正常加载与渠道信息展示
- 验证渠道配置中的同步模板功能
- 验证 Token 过期后的自动重新登录处理

## 2. 前置条件

### 2.1 环境前置条件
1. UAT 环境服务正常运行，控制台可正常访问
2. 营销云页面可通过控制台卡片跳转正常加载
3. 用户已拥有 DTCloud 控制台的有效账号
4. 浏览器兼容：Chrome / Edge 最新版本

### 2.2 数据前置条件
1. 消息管理中至少存在 38 条以上的消息模板记录（用于列表展示和分页验证）
2. 消息模板中存在不同状态（启用、禁用）的记录
3. 消息模板覆盖不同的渠道类型和消息类型
4. 至少存在一条渠道配置记录（如 wxTmplSenderExt 点单订阅消息）
5. 测试账号具有消息管理菜单的可见权限和完整操作权限

### 2.3 每次用例执行的初始状态
- 用户已退出登录（或处于未登录状态），控制台登录页面可访问
- 测试用例执行前，确保消息模板状态可恢复（如需验证启用/禁用，记录操作前状态）
- 对于 TC-1 到 TC-7，假设 Token 有效，无需重新登录
- 对于 TC-8，需要模拟 Token 过期场景

## 6. 风险与注意事项

### 6.1 已知风险

| 风险编号 | 风险描述 | 影响范围 | 缓解措施 |
|---------|---------|---------|---------|
| R1 | 测试环境不稳定，控制台登录页面不可用 | TC-1, TC-8 | 测试前确认环境可用性；设定适当的超时和重试机制 |
| R2 | 消息模板数据被其他测试修改（启用/禁用状态变更） | TC-4 | 每个测试用例执行前后记录状态；使用独立的测试数据 |
| R3 | 渠道配置数据的同步模板操作可能影响生产数据 | TC-7 | 确认在 UAT 环境执行，不会影响生产数据 |
| R4 | 新标签页打开可能被浏览器拦截 | TC-1 | 确保自动化浏览器的弹窗设置允许新标签页打开 |
| R5 | Token 过期场景模拟可能影响浏览器 Session | TC-8 | Token 过期测试放在最后执行；清除测试数据后恢复 Session |

### 6.2 注意事项

1. **新标签页处理**：TC-1 步骤 6 中点击"数盈·营销云"卡片会打开新标签页，自动化脚本必须正确处理 `context.on('page')` 事件以获取新标签页的引用
2. **等待策略**：页面加载和数据刷新时，建议使用显式等待（如 `waitForSelector`、`waitForResponse`）而非固定延时
3. **启用/禁用操作可逆性**：TC-4 中修改模板状态后，建议在测试结束后将状态恢复原状，避免影响其他测试
4. **渠道配置禁用操作**：TC-7-002 中禁用渠道配置属于高风险操作，建议仅在独立测试环境执行，或在测试后立即恢复
5. **分页数据依赖**：测试计划假设分页显示"共 38 条"，实际数据量可能随测试执行而变化，脚本应动态获取总数而非硬编码
