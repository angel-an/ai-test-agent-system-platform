### 6.2 评论 403 真相：**端点路径错了，不是权限**（已实锤修正）

之前我对 6 个评论路径逐一 403 后推断"集成 token 权限面不含评论"——**这个结论是错的**。
实锤：翻出 10-21 给 `dmcloud-saas-67197` 成功发过评论的历史脚本（`idp_67197_comment.py`，老工作区），
它用的 token 与本次**完全相同**，端点却是另一种形态：

```
POST /agile/v1/projects/{p}/issue_comment        ← 单数 issue_comment、项目级、不挂 issues 下、无 organizationId 头
body: {"issueId": <I>, "commentText": "<Quill Delta 的 JSON 字符串>"}
```

即：网关对不存在的路径返回的是 `PERMISSION_MISMATCH`(403) 而不是 404，我被这个响应码误导了。
**403 ≠ 无权限，先怀疑路径。**（经验已记入项目记忆。）

### 6.3 关单实现口径（踩坑记录）

- 关单**不需要**走工作流接口，直接 `PUT /agile/v1/projects/{p}/issues` 带 `statusId: 41` 即可（HTTP 201）
- `statusId 41` = 已关闭（`type=done`）；`statusId 4` = 已完成（`type=done`）——两个都属 done 态但语义不同
- `description` 必须是 **Quill 裸数组** `json.dumps([{...}])`；历史脚本 `xy_idp_close_931769.py` 用的
  `{"ops": [...]}` 格式会让 IDP 前端**渲染全空白**，本次未沿用
- payload 只带 `issueId` + `objectVersionNumber` + `statusId` + `description`（多带 `projectId` 会报 `verifyUpdateData.noField`）
