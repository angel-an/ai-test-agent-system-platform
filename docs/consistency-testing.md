# 框架指引：写后读一致性验证

本指引适用于所有存在异步落库、缓存刷新、消息消费或读写分离的接口。它是测试框架约束，不绑定项目、接口、账号或字段。

公共能力为 `app.utils.consistency.wait_for_consistency`。项目适配层只负责提供写操作、只读查询、匹配条件和已确认的字段映射。

## 接入约束

- 只有接口契约明确存在最终一致性时才启用轮询；同步接口继续即时断言。
- 轮询只能重复只读查询，禁止重复执行业务写操作。
- `timeout`、`interval` 必须由环境或测试配置注入并记录到报告；默认值只是诊断兜底，不代表业务 SLA。
- 写成功后先校验 HTTP 状态、业务码和业务成功集合，再开始查询。
- 查询字段、账户唯一性、金额精度必须由项目契约显式配置，禁止猜字段或静默回退。
- 金额统一使用 Decimal；不得用足以掩盖最小业务金额的宽泛容差。
- 共享数据必须串行或使用框架级独占资源；禁止依赖测试文件顺序保证隔离。
- 超时必须保留每次查询的时间、结果、关联标识和配置，状态为“一致性超时/待定位”，不能自动归因服务缺陷。
- 交易流水只有在存在可靠关联键时才能断言；不能用相近时间的流水代替关联。
- 自动重试写操作、自动冲正和自动补偿默认关闭，必须由业务策略显式授权。

## 结果分类

`passed` 表示首次查询已满足条件，`passed_after_wait` 表示轮询后满足条件，`CONSISTENCY_TIMEOUT` 表示观察窗口内未满足条件。超时后应按“时序/缓存、查询字段、数据隔离、服务实现”顺序归因。

## 项目适配层要求

项目不得修改公共组件来写入项目常量。应在项目配置中提供一致性模式、轮询窗口、查询函数、目标匹配函数、金额字段、账户隔离策略、流水关联键和证据脱敏规则。测试报告展示通用字段，项目名称、接口路径和业务字段作为参数填充。
