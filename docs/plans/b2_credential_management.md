# 测试凭据管理规范（B2）

> 通用规范，不绑定具体项目。
> 目标：任何 live 测试的凭据都统一存储、最小权限、可审计、可轮换。

---

## 1. 凭据分级

| 等级 | 类型 | 示例 | 存储要求 |
|---|---|---|---|
| 密钥 | 加密/签名密钥 | API key、私钥、签名秘钥 | 专用密钥系统（Vault/KMS） |
| 凭据 | 认证信息 | token、Cookie、session、密码 | 环境变量或密钥系统 |
| PII | 个人身份信息 | 手机号、姓名、地址、会员 ID | 脱敏后使用，禁止明文存储 |

**原则**：凭据和密钥独立管理，不与其他数据混用。

---

## 2. 存储方式

### 2.1 环境变量（推荐，开发和测试环境）

```bash
# .env 文件（不提交到版本控制，已加入 .gitignore）
PR2_API_USER=andan
PR2_API_PASSWORD=***        # 真实值由运维或 QA 本地配置
PR2_ACCESS_TOKEN=***        # 短期有效，定期轮换
PR2_COOKIE_HEADER=***       # 同上

PR9_MEMBER_ID=M001          # 测试会员 ID
PR9_MEMBER_TOKEN=***        # 会员会话 token
PR9_CRM_ADMIN_TOKEN=***     # CRM 管理员 token
```

**要求**：
- `.env` 文件已加入 `.gitignore`，禁止提交到版本控制
- 生产环境凭据不进入开发/测试环境
- 不同项目使用不同前缀（`PR2_`、`PR9_`），避免冲突

### 2.2 密钥管理系统（生产环境或高敏感场景）

| 系统 | 适用场景 | 责任人 |
|---|---|---|
| HashiCorp Vault | 动态凭据、短期 lease | 运维 |
| AWS KMS / 阿里云 KMS | 云原生密钥管理 | 运维 |
- 密钥申请 → 最小权限使用 → 立即归还

## 3. 禁止行为清单

| 禁止项 | 正确做法 |
|---|---|
| ❌ 密码/token 硬编码在脚本中 | ✅ 读取环境变量 |
| ❌ 密码/token 写入报告或截图 | ✅ 报告只记录"已使用环境变量" |
| ❌ 密码/token 输出到日志 | ✅ 日志记录"凭据已使用"，不记录值 |
| ❌ 密码/token 通过 IM/邮件传输 | ✅ 通过密钥系统或安全通道传输 |
| ❌ 长期有效的 token 不轮换 | ✅ 设置有效期，定期轮换 |
| ❌ 不同项目共用同一凭据 | ✅ 项目隔离，不同前缀/不同密钥 |

---

## 4. 有效期与轮换

| 凭据类型 | 建议有效期 | 轮换责任人 | 轮换触发条件 |
|---|---|---|---|
| 登录密码 | 90 天 | 运维/QA | 定期轮换、人员变动、泄露怀疑 |
| access-token | 7-30 天 | QA | 过期前主动轮换、异常使用后强制轮换 |
| Cookie/session | 单次会话 | QA | 每次执行后清理 |
| API key | 按密钥系统策略 | 运维 | 定期轮换、权限变更 |

**轮换记录**：
- 轮换时间、旧凭据失效时间、新凭据生效时间
- 轮换原因（定期/异常/人员变动）
- 责任人确认

---

## 5. 审计要求

每次凭据使用记录：

| 字段 | 内容 |
|---|---|
| 时间 | 使用时间点 |
| 操作人 | QA/开发/运维账号 |
| IP/机器 | 执行环境标识 |
| 凭据类型 | token/password/Cookie/API key |
| 用途 | 登录/执行 API/执行 Web/其他 |
| 项目 | PR-2/PR-9/其他 |
| 结果 | 成功/失败 |

**存储**：审计日志写入独立系统或文件，与测试日志分离。

---

## 6. 泄露响应

```
发现泄露 → 立即失效凭据 → 通知安全团队 → 排查影响范围 → 轮换所有相关凭据 → 复盘
```

| 步骤 | 责任人 | 时限 |
|---|---|---|
| 发现泄露 | 任何人员 | 立即 |
| 失效凭据 | 运维/QA | 30 分钟内 |
| 通知安全团队 | 发现人 | 1 小时内 |
| 排查影响范围 | 安全团队 + 业务 | 4 小时内 |
| 轮换相关凭据 | 运维 | 24 小时内 |
| 复盘 | 团队 | 72 小时内 |
