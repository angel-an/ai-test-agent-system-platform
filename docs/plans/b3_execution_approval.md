# 测试执行审批规范（B3）

> 通用规范，不绑定具体项目。
> 目标：任何 L2/L3 写入操作都有审批记录，可追溯、可复核。

---

## 1. 审批分级

| 执行风险等级 | 审批要求 | 审批方式 | 留痕要求 |
|---|---|---|---|
| L0（本地模拟） | 无需审批 | 自动执行 | 记录日志 |
| L1（UAT 只读） | 无需审批 | 自动执行 | 记录查询范围 |
| L2（可回滚写入） | 需业务确认 | 口头/邮件/系统确认 | 记录确认人和时间 |
| L3（风险或不可逆） | 需书面审批 | 书面审批单或系统审批流 | 完整审批记录 |
| 凭据/密钥使用 | 需密钥申请 | 密钥系统申请 → 最小权限使用 | 使用记录 |

**原则**：
- 默认按最高风险等级处理（fail-closed）
- 降级需明确理由和责任人
- 审批未完成前禁止执行

## 2. 必须审批的操作清单

| 操作类型 | 风险等级 | 审批要求 | 示例 |
|---|---|---|---|
| 账户充值 | L2 | 业务确认 | PR-2 储值充值 |
| 账户退款/冲正 | L3 | 书面审批 + 流水核对 | PR-2 退款 |
| 积分兑换 | L2 | 业务确认 | PR-9 积分兑换 |
| 批量导入 | L2 | 业务确认 | PR-2 会员批量导入 |
| 商品配置新增 | L2 | 业务确认 | PR-9 CRM 商品新增 |
| 装修配置修改 | L2 | 业务确认 | PR-9 CRM 装修 |
| 风险负向测试 | L3 | 书面审批 + 回滚方案 | 边界值、并发、安全测试 |
| 凭据/密钥使用 | — | 密钥申请 | Vault/KMS 凭据获取 |

**无需审批的操作**：
- 只读查询（余额查询、商品列表、交易记录）
- 本地模拟数据操作
- 登录获取 token（但 token 使用需按凭据管理规范）

## 4. 审批流程

```
L0/L1：自动执行，记录日志
  → L2：业务确认（口头/邮件/系统）→ 执行 → 留痕
    → L3：书面审批 → 回滚方案确认 → 执行 → 留痕 → 复核
      → 凭据/密钥：密钥申请 → 最小权限使用 → 立即清理
```

### 4.1 L2 流程

1. QA 填写 L2 确认记录（操作内容、影响范围、回滚方式）
2. 业务确认（口头/邮件/系统）
3. QA 执行
4. 记录执行结果
5. （可选）复核

### 4.2 L3 流程

1. QA 填写 L3 审批申请（操作内容、数据范围、金额、回滚方案）
2. 业务负责人审批
3. 回滚方案确认（责任人签字或系统确认）
4. QA 执行
5. 记录执行结果
6. 复核人复核（不同于执行人）
7. 记录复核结论

## 5. 审批记录归档

| 项目 | 归档位置 | 保留期限 |
|---|---|---|
| L2 确认记录 | `workspace/approvals/{project}/l2/` | 项目结束后 30 天 |
| L3 审批记录 | `workspace/approvals/{project}/l3/` | 项目结束后 90 天 |
| 凭据使用记录 | `workspace/audit/{project}/` | 按安全策略 |

**命名规范**：
- L2：`l2-{操作}-{timestamp}.md`
- L3：`l3-{操作}-{timestamp}.md`
