# 测试数据回滚机制规范（B4）

> 通用规范，不绑定具体项目。
> 目标：任何 L2/L3 写入操作都有明确的回滚方式，可执行、可验收、有责任到人。
> **注意**：本规范定义回滚方案，真实冲正仍需业务授权，不得擅自操作生产数据。

---

## 1. 回滚分级

| 回滚难度 | 定义 | 适用场景 | 责任人 |
|---|---|---|---|
| 自动回滚 | 系统或脚本自动恢复初始状态 | token 过期、会话清理 | QA |
| 简单回滚 | 单条记录删除或标记 | 测试数据标记为删除 | QA / 开发 |
| 标准回滚 | 冲正或补偿操作 | 充值退款、积分补充 | QA / 业务 |
| 复杂回滚 | 多表关联、人工核对 | 批量导入、复杂交易 | 业务 / 开发 / DBA |

---

## 2. 按操作类型的回滚方案

### 2.1 账户充值（PR-2 示例）

| 字段 | 内容 |
|---|---|
| 操作 | 会员账户充值 |
| 风险等级 | L2 |
| 回滚方式 | 退款冲正 |
| 具体步骤 | 1. 记录充值前余额<br>2. 执行充值<br>3. 核对余额 = 原余额 + 充值金额<br>4. 如需回滚：调用退款接口（type=1）或人工核对后冲正 |
| 验收条件 | 退款后余额 = 充值前余额 |
| 责任人 | QA / 业务 |
| 注意事项 | 退款金额必须与充值金额一致；流水记录需对应 |

### 2.2 账户退款/冲正（PR-2 示例）

| 字段 | 内容 |
|---|---|
| 操作 | 账户退款 |
| 风险等级 | L3 |
| 回滚方式 | 人工核对后补充值；或记录冲正流水 |
| 具体步骤 | 1. 记录退款前余额<br>2. 执行退款<br>3. 核对余额 = 原余额 - 退款金额<br>4. 如需回滚：人工核对后补充值，或记录冲正流水 |
| 验收条件 | 补充后余额 = 退款前余额 |
| 责任人 | QA / 业务 / 开发 |
| 注意事项 | 退款为不可逆操作，必须提前审批；冲正需业务授权 |

### 2.3 积分兑换（PR-9 示例）

| 字段 | 内容 |
|---|---|
| 操作 | 积分兑换商品 |
| 风险等级 | L2 |
| 回滚方式 | 人工核对后补充积分；或记录冲正流水 |
| 具体步骤 | 1. 记录兑换前积分余额<br>2. 执行兑换<br>3. 核对积分 = 原积分 - 兑换积分<br>4. 如需回滚：人工核对后补充积分值，或记录冲正流水 |
| 验收条件 | 补充后积分 = 兑换前积分 |
| 责任人 | QA / 业务 |
| 注意事项 | 兑换订单状态需同步处理（取消或标记测试） |

### 2.4 批量导入（PR-2 示例）

| 字段 | 内容 |
|---|---|
| 操作 | 会员账户批量导入 |
| 风险等级 | L2 |
| 回滚方式 | 删除导入记录或标记为测试数据 |
| 具体步骤 | 1. 记录导入前数据状态<br>2. 执行批量导入<br>3. 核对导入记录数 = 文件行数<br>4. 如需回滚：删除导入记录或标记为测试数据 |
| 验收条件 | 导入记录已清理或标记 |
| 责任人 | QA / 业务 |
| 注意事项 | 批量导入影响多条记录，回滚需逐条核对 |

### 2.5 商品配置新增（PR-9 示例）

| 字段 | 内容 |
|---|---|
| 操作 | CRM 积分商品新增 |
| 风险等级 | L2 |
| 回滚方式 | 删除商品配置或标记为测试数据 |
| 具体步骤 | 1. 记录新增前商品列表<br>2. 执行新增<br>3. 核对商品列表包含新增项<br>4. 如需回滚：删除商品配置或标记为测试数据 |
| 验收条件 | 测试商品已清理或标记 |
| 责任人 | QA / 业务 |
| 注意事项 | 商品配置可能影响 App 展示，回滚需确认无线上影响 |

### 2.6 装修配置修改（PR-9 示例）

| 字段 | 内容 |
|---|---|
| 操作 | CRM 积分商城装修配置修改 |
| 风险等级 | L2 |
| 回滚方式 | 恢复上一版本配置 |
| 具体步骤 | 1. 记录修改前配置版本<br>2. 执行修改<br>3. 核对配置已变更<br>4. 如需回滚：恢复上一版本配置 |
| 验收条件 | 配置恢复为修改前状态 |
| 责任人 | QA / 业务 |
| 注意事项 | 修改前必须备份当前配置版本 |

## 3. 回滚方案验证（测试环境）

在真实执行前，建议在测试环境验证回滚方案：

| 验证项 | 方法 | 通过标准 |
|---|---|---|
| 充值 → 退款 | 测试环境小额充值后退款 | 退款后余额 = 充值前余额 |
| 兑换 → 补充积分 | 测试环境兑换后补充积分 | 补充后积分 = 兑换前积分 |
| 导入 → 删除 | 测试环境批量导入后删除 | 导入记录已清理 |
| 配置修改 → 恢复 | 测试环境修改后恢复上一版本 | 配置恢复为修改前状态 |

**注意**：验证回滚方案不等于真实回滚，验证通过后仍需按审批流程执行真实操作。

## 4. 流水核对规范

任何涉及金额/积分的操作，必须核对流水：

| 核对项 | 方法 |
|---|---|
| 充值后余额 | 充值前余额 + 充值金额 = 充值后余额 |
| 退款后余额 | 退款前余额 - 退款金额 = 退款后余额 |
| 兑换后积分 | 兑换前积分 - 兑换积分 = 兑换后积分 |
| 流水记录数 | 操作次数 = 流水记录数 |
| 流水方向 | 充值/补充为正，退款/兑换为负 |

**核对记录**：
- 核对时间、核对人
- 操作前余额/积分、操作后余额/积分
- 差异说明（如有）

| 流水核对 | 已核对 / 差异说明 |
| 验收人 | （不同于执行人） |
| 验收结论 | 通过 / 不通过 |
