# 平台后续工作流规划（2026-09-06）

> 本文档将后续工作拆分为 4 条独立工作流，彼此解耦，不扩展平台主功能。
> 平台代码层（`backend/app/platform/` + `backend/tests/platform/`）保持冻结。

---

## 工作流 1：P0-A 真实项目接入

目标：新项目可以独立完成"需求 → 用例 → API/Web 测试 → 报告归档"，且没有业务代码进入平台层。

| 任务 | 内容 | 交付物 |
|---|---|---|
| A1 接入登记 | 项目、环境、负责人、需求文档、测试范围 | 项目接入单 |
| A2 需求映射 | 需求模块映射到测试用例契约和覆盖维度 | 需求-用例矩阵 |
| A3 测试数据准备 | 账号、会员、余额、权限、订单等前置数据 | 测试数据清单 |
| A4 用例生成审核 | 生成用例、质量门禁、产品确认待确认项 | 用例快照和审核记录 |
| A5 API/Web 执行 | 先只读，再正向写入，最后风险负向 | API/Web 执行记录 |
| A6 结果归档 | 统一报告、截图、响应、失败项和复验结论 | 项目交付包 |

**验收标准**：
- 新项目按 A1→A6 流程独立完成接入
- 项目专属代码不进入 `app/platform/` 或 `tests/platform/`
- 项目样例仅用于验证平台能力，不定义平台规则

---

## 工作流 2：P0-B 测试数据与凭据治理

目标：任何 live 测试都能回答"谁批准、写了什么、影响多少、如何恢复"。

| 任务 | 内容 | 交付物 |
|---|---|---|
| B1 数据分级 | 只读、正常写入、风险写入、敏感数据分类 | 数据分级表 |
| B2 凭据管理 | 环境变量或密钥系统，禁止写入脚本和报告 | 凭据配置说明 |
| B3 执行审批 | 写入、退款、删除、边界负向必须有业务确认 | 执行审批记录 |
| B4 回滚机制 | 明确流水核对、冲正、数据恢复责任人 | 冲正/回滚方案 |
| B5 证据脱敏 | token、Cookie、手机号等敏感内容脱敏后归档 | 脱敏规则和检查结果 |
| B6 数据清理 | 项目结束后核对测试数据和残留流水 | 数据清理记录 |

**验收标准**：
- 每次 live 执行都有审批记录
- 凭据不硬编码在脚本或报告中
- 敏感数据已脱敏
- 回滚方案可执行

---

## 工作流 3：P1-C 项目接入规范固化

目标：将真实项目接入经验沉淀为可复用规范。

| 任务 | 内容 | 交付物 |
|---|---|---|
| C1 接入模板 | 统一项目目录、环境变量、测试计划和报告模板 | 项目模板 |
| C2 执行分层 | 固定只读、正向、复合、风险负向执行顺序 | 执行手册 |
| C3 角色分工 | 平台、QA、开发、产品、运维职责明确 | RACI/职责表 |
| C4 交接检查 | 用例、脚本、证据、遗留项完整性检查 | 交付检查表 |
| C5 复验规则 | 缺陷修复后只重跑关联场景和回归基线 | 复验记录模板 |

**验收标准**：
- 新项目可直接套用 C1 模板
- 执行顺序符合 C2 分层要求
- 角色分工无歧义
- 交接检查无遗漏

## 工作流 4：P2 P4/P5 独立维护项

### P4：Pytest Collection Warning 处理

| 步骤 | 内容 |
|---|---|
| 1 | 统计每条警告来源（当前 10 条：平台层 8 + MongoDB 模型 2） |
| 2 | 评估重命名领域模型、增加 `__test__ = False` 或调整导入方式的影响 |
| 3 | 选择最小改动方案 |
| 4 | 单独提交并回归验证 243 项基线 |

**验收标准**：警告减少或清零，且不改变领域模型对外接口。

### P5：测试样例字符串统一

| 步骤 | 内容 |
|---|---|
| 1 | 扫描平台测试中的业务词、真实手机号和项目代号 |
| 2 | 只替换平台测试样例为中性数据 |
| 3 | 保留 PR-2/PR-9 项目目录中的真实业务样例 |
| 4 | 运行平台基线并检查文档引用 |

**验收标准**：平台层无项目专属数据，真实项目证据不被误改。

## 推荐执行顺序

```
B（测试数据与凭据治理）
  → A（接入一个真实项目验证流程）
    → C（根据 A 的问题补充接入规范）
      → P4/P5（按实际收益决定）
```

**原则**：
1. 先做 B，确保数据安全和审批闭环
2. 再做 A，用真实项目验证 B 的有效性
3. 根据 A 的问题补充 C，沉淀规范
4. P4/P5 放在最后，不阻塞真实项目接入

**不建议**：
- 把 P4/P5 放在真实项目接入之前
- 把真实项目测试数据纳入平台基线
- 扩展平台主功能（`app/platform/` 保持冻结）
