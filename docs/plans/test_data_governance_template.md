# 测试数据分级与治理模板

> 通用模板，不绑定具体项目数据结构。
> 项目接入时按此模板填充，确保任何 live 测试都能回答：
> "谁批准、写了什么、影响多少、如何恢复"。

---

## 数据分级标准

### 执行风险等级（操作维度）

| 等级 | 名称 | 定义 | 执行要求 |
|---|---|---|---|
| L0 | 本地模拟数据 | 纯内存/模拟数据，无外部依赖 | 可自动执行，无需审批 |
| L1 | UAT 只读数据 | 仅查询，不修改任何状态 | 默认可执行，记录查询范围 |
| L2 | 可回滚正常写入 | 创建、常规修改，可冲正或恢复 | 需业务确认，留痕，有回滚方案 |
| L3 | 风险或不可逆操作 | 退款、删除、边界负向、并发压力 | 需审批、留痕、回滚方案、责任人 |

### 数据敏感等级（数据维度）

| 等级 | 名称 | 定义 | 处理要求 |
|---|---|---|---|
| 普通 | 公开/测试数据 | 测试商品名称、配置参数、排序值 | 无需脱敏 |
| PII | 个人身份信息 | 手机号、姓名、地址、会员等级 | 脱敏后使用，禁止明文存储 |
| 凭据 | 认证信息 | token、Cookie、session、密码 | 环境变量或密钥管理，禁止硬编码 |
| 密钥 | 加密/签名密钥 | API key、私钥、签名秘钥 | 专用密钥系统，最小权限 |

**分级原则**：
- 执行风险与数据敏感独立评估，取交集确定最终管控强度
- 默认按最高风险等级处理（fail-closed）
- 降级需明确理由和责任人
- 凭据和密钥独立管理，不与其他数据混用

## 数据登记模板

| 字段 | 内容 | 示例 |
|---|---|---|
| 项目/环境 | 项目标识、环境（DEV/UAT/PROD） | DEMO-1 / UAT |
| 数据对象 | 账号、会员、余额、订单、权限等 | 会员账户余额 |
| 数据标识 | 脱敏后的手机号/ID，不记录 token | 139****0001（示例） |
| 操作类型 | 查询、创建、修改、退款、删除 | 账户充值（创建流水+修改余额） |

| 数据保留期限 | 测试期间、项目结束后清理时间 | 项目结束后 7 天内清理 |
| 责任人 | QA、业务、开发或运维 | QA：xxx / 业务：yyy |

## 凭据管理规范

| 事项 | 要求 |
|---|---|
| 存储方式 | 环境变量或密钥管理系统（如 Vault、KMS） |
| 禁止行为 | 硬编码在脚本、报告、日志、截图中 |
| 传输方式 | HTTPS/TLS，禁止明文传输 |
| 有效期 | 短期有效，定期轮换 |
| 审计要求 | 每次使用记录时间、IP、操作人 |
| 泄露响应 | 立即失效、通知安全团队、排查影响范围 |

## 执行审批流程

```
L0/L1：自动执行，记录日志
  → L2：业务确认（口头/邮件/系统）→ 执行 → 留痕
    → L3：书面审批 → 回滚方案确认 → 执行 → 留痕 → 复核
      → 凭据/密钥：密钥申请 → 最小权限使用 → 立即清理
```

**审批记录要素**：
- 申请人、审批人、时间
- 操作内容、影响范围
- 回滚方案、责任人
- 执行结果、复核结论

## 数据清理检查表

| 检查项 | 状态 |
|---|---|
| 测试账号是否已注销或恢复初始状态 | ☐ |
| 测试流水是否已冲正或标记为测试数据 | ☐ |
| 测试文件（截图、报告）是否已脱敏归档 | ☐ |
| 敏感数据（token、Cookie）是否已从环境变量中移除 | ☐ |
| 证据包是否已按保留期限处理（保留/清理） | ☐ |
| 责任人是否已确认无残留影响 | ☐ |

---

## 使用说明

1. **项目接入时**：按"数据登记模板"逐条登记测试数据
2. **执行前**：核对风险等级和审批状态
3. **执行后**：按"数据清理检查表"核对残留
4. **归档时**：敏感数据脱敏，凭据清理，证据留痕

**注意**：本模板为通用治理规则，不替代具体项目的业务审批流程。
