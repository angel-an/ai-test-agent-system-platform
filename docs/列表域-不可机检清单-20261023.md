### 三之实测更新（2026-10-26，TR-827 真实通道）

原先的处置假设是「建子功能后即可自动翻出」。**实测证否**：

- 已建子功能 `yl-masterdata-import-task`（WSF-48576978）+ 路径模板，走真实通道后探明
  **Master Data Management 的子菜单全集只有 5 项**：
  `Order List / Brand Management / Shop Management / Item Manage / Payment Method`
  —— **没有「導入任務 / Import …」这一类菜单**（探针输出见 TR-827 的 `YL_SUBMENU_DUMP`）。
- 因此"導入任務列表"不是独立菜单页；按需求描述它应是**导入动作之后**产生的任务列表
  （弹层/页内标签页），而规则文本没有给出"从哪个页面的哪个动作进入"。
- 结论：本条的阻塞点不是"缺子功能"，而是**缺可达入口**。当前状态：子功能与绑定保留
  （便于后续接），断言（排序 創建時間 desc）已能编译出来，但导航必然止步于菜单点击。

**怎么补**（择一）：
1. 需求侧补充入口路径：「商品/店鋪列表页 → 点击 Import → 导入任务列表」，并说明任务列表是
   弹层、抽屉还是独立路由；据此在子功能配 `child_labels` 到**真实可点的入口**（如
   `Item Manage` 进列表后再点 Import，需新增"页内动作"前置，属模板能力扩展）。
2. 或认定该条为人工验证项，从自动化范围剔除。


## 怎么补才能被机检

1. **排序**：规则文本写「按 <列名> 近→遠 / 遠→近」（或 升序/降序），列名需与页面表头一致。
2. **列清单**：写「列表顯示欄位（N列）：<列1>、<列2>…」，**N 必须等于列出的个数**（声明 15 实列 14 会被拒绝并写明差在哪，不硬凑）。
3. **筛选**：给「输入值 → 期望命中/不命中」一对样例（如：`按店鋪編號 "ST0001" 精準查 → 结果仅 1 条`）。
4. 上述任意一种补进 `requirement_rule.rule` 文本即可，**无需改代码**——重新编译时解析器自动翻出。
