## 五、「店铺列表 0 行数据」——结论：不成立，数据一直在

### 5.1 实测证据（本机 Playwright 直连 UAT，同账号 `lianqiao`）

| 观测点 | 结果 |
|---|---|
| 接口 `GET /yundt-saas-gateway/api/icdp/v1/org/shop/list?pageNum=1&pageSize=10&orgSearchStatus=1` | **HTTP 200，`endRow=9`（10 条）** |
| DOM `.ant-table-tbody` 数据行 | **10 行，全部可见**（`offsetParent !== null`） |
| 首行内容 | `15805 / 店铺名称-中文 / Shop Name EN / 内部名称-中文 / YLaa / Fast Food / Business Enabled …` |
| 表头 | 16 个 `th`，与 TR-830 完全一致 |
| 连续 25 秒采样（1s 一次） | 行数恒为 10，未出现空态、未出现 0 行 |

### 5.2 那 `no_rows` 是怎么来的

TR-830 的现场日志顺序：

```
YL_NAV_RETRY {"action":"reload","reason":"menu_not_expanded"}   ← 菜单首次展开失败，整页 reload 重走
YL_LIST_READY {"rendered":true,"attempts":3,"elapsedMs":1273}   ← 只用了 1.27s 就判定"就绪"
COLUMN_HEADERS {"count":16,...}                                  ← 表头读得到
SORT_TRACE {"name":"sort:更新時間:desc","why":"no_rows"}          ← 紧随其后采样，0 行
```

根因：**「就绪」判据只看表格骨架（`.ant-table` 可见），不看数据行**。
antd 的渲染顺序是「thead 先出 → 数据接口回来 → tbody 挂行」，
旧判据在 thead 出来那一刻就通过（1.27s），排序采样正好落在「表格已渲染、数据还没挂上」的窗口里。
reload 之后应用要重新拉 token/字典/组织/店铺列表，这个窗口被拉宽，所以只在 reload 的那次跑里踩中。
数据本身没有消失——是**采样早于数据落地**。

### 5.3 rev204 修复（提交内容见 git）

| 改动 | 位置 |
|---|---|
| `YL_LIST_READY` 判据：表格可见 **且**（数据行 >0 **或** 空态提示出现），日志带 `rows` / `empty` | `web_case_link_service._generate_yl_masterdata_script` |
| `sortColumnSample`：tbody 无数据行时轮询等待（400ms × 最多 12s），超时才判 `no_rows`，并输出 `waitedMs` | `web_case_link_service._SORT_DIAG_TEMPLATE` |

`COMPILER_REV=rev204`，digest `fb0c0e2918ea`。

**影响面**：真·空列表页不会变慢（有 `.ant-table-placeholder` 就直接放行）；
真·空且无空态文案的页面最多多等 12s 再落 `no_rows`（原口径不变）。
