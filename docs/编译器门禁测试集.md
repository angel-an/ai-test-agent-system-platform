# 编译器门禁测试集

> 一句话：**改 `web_case_compiler.py` 之后，必须先跑这一条命令**。
> 它是「三分钟内能变绿」的那一层，用来替代「等一小时的全量」和「靠 grep 猜该跑哪些」。

## 一条命令

```bash
cd backend
..\.venv\Scripts\python.exe -X utf8 scripts\run_compiler_gate.py
```

- `--list`：只看本次范围（自动发现 + 排除清单）
- `--bisect`：逐文件跑并输出耗时表（定位慢点/卡点，别人工二分）
- 退出码：`0` 全绿 / `1` 有失败 / `2` 清单失效（发现集为空、解析不到汇总行）

## 三层口径（不得相加、不得互相替代）

| 层 | 命令 | 规模（2026-10-23 实测） | 什么时候跑 |
| --- | --- | --- | --- |
| **P0 基线** | `scripts\gen_p0_baseline.py` | 719 passed | 交付/发布前，证明平台主链路可用 |
| **编译器门禁**（本文） | `scripts\run_compiler_gate.py` | **30 文件 / 109s / 567 passed** | 每次改编译器、改执行器模板、bump rev 后 |
| **全量** | `pytest tests/` | 2830 条 / 约 60 分钟（1.27s/条） | 大改合入前 |

三层的覆盖重点不同：P0 盯 `tests/platform` + api 资产链路；门禁盯 `web_case_compiler`
（编译、执行器模板、回显、对账）；全量才包含其余工作流。

## 范围怎么定的

不维护手写文件清单（会漂），按**依赖关系**自动发现：

> 测试文件正文出现 `web_case_compiler` / `_FORM_EXECUTOR_TS` / `render_form_executor` /
> `build_form_plan` 任一 ⇒ 属于门禁集。

新增依赖编译器的测试**自动纳入**，不需要改清单。

### 排除项（集成/环境依赖，失败无法区分代码与环境）

| 文件 | 理由 |
| --- | --- |
| `tests/test_web_negative_scenario_browser_local.py` | 拉真实浏览器跑负路径场景（依赖 UAT 可达） |
| `tests/test_web_toolbar_modal_browser_local.py` | 拉真实浏览器验证工具栏/弹窗（依赖 UAT 可达） |
| `tests/test_web_upload_browser_local.py` | 拉真实浏览器验证上传控件（依赖 UAT 可达） |
| `tests/test_web_upload_local_node.py` | 起本地 Node 跑上传脚本（依赖 node 与临时目录） |
| `tests/test_shell_policy.py` | 需要 anthropic 包（本机 managed python 未装，收集即失败） |

`tests/test_compiler_gate_manifest.py` 会锁住这份清单：排除项指向不存在的文件、
理由写得敷衍、真实浏览器测试混进门禁集 —— 都会红。

## 为什么会有这一层（两个被埋的红线）

建立门禁集的直接触发是 2026-10-23 的一次排查：

1. 全量跑「17 分钟没结束」被当成挂死。实际逐个跑才发现：**2830 条 × 1.27s ≈ 60 分钟**，
   只是体量，不是死锁；被怀疑的那条用例单独跑 17.4s 正常通过。
2. 顺着查下去，发现两条**长期红着**的测试：

   | 测试 | 断言 | 从哪一版开始红 |
   | --- | --- | --- |
   | `test_anchored_error_rev140.py::test_rev_bumped` | 钉死 `COMPILER_REV = "rev180"` | rev181（此后每 bump 一次红一次，直到 rev196） |
   | `test_submit_resubmit_reconcile_rev139.py::test_reconcile_counts_resubmission_separately` | 钉死 `summary.total - (...)`，实现 rev165 已改为 `emitted_raw -` | rev165 |

   两条都是「追字面量」留下的：有人为了让它变绿，把断言里的版本号/字段名追到当时的实现，
   而不是改成不随实现漂移的判据。没人跑，就一直红着。

**结论写在机制里，不写在自觉里**：判据要写成「≥ 引入该测试的版本」而不是具体版本号；
每次改编译器都跑这条命令，红线活不过一个提交。

## 维护约定

1. 新增依赖编译器的测试 → 自动纳入，不要手工登记；
2. 新增必须排除的文件 → 写进 `backend/tests/compiler_gate_manifest.py::INTEGRATION_EXCLUDED`
   并写清「依赖什么」（会有一条参数化测试逐条检查理由）；
3. 不在清单里写死用例数量 —— 数字由执行决定；
4. 门禁超过 `SPEED_BUDGET_SECONDS`（默认 300s）会打警告：门禁太慢就会被跳过，
   这时用 `--bisect` 找慢点，而不是把预算调大。
